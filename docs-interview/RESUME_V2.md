### C-1 纯 AI 应用版（两项目讲透，前端一句带过）

> 每条统一按「**痛点 → 选型/做法 → 收益**」写，体现技术不是堆名词而是解决了具体问题。

**马小i · 企业级多智能体助手（Assistant 单入口分层调度）** · 独立设计与实现
`Python / FastAPI / LangGraph / LangChain / MCP / A2A / Redis Stack / Neo4j / PostgreSQL / LangSmith + 自建 Langfuse / Docker`
- 【痛点】员工诉求散在多个内部系统、问法五花八门，单一线性 pipeline 撑不住「可分支、可回环、跑到一半可续跑」。【选型】用 LangGraph 编排单入口分层调度图（`build_context → rewrite_query → classify_intent → 分派 → persist_memory`），把每个节点做成审计单位、以同一 `trace_id` 串联，并把指代消解与平台时钟**前置于意图识别**让分类器与全部路由共享同一份结果。【收益】检索不足可条件边回环重检、会话中断可 checkpoint 续跑，任一轮都能定位到具体节点。
- 【痛点】每轮都调 LLM 做意图分类，成本高、延迟大且判定不可解释。【选型】三层意图漏斗：规则快筛 → bge-m3 种子集语义分类（Top-K 均值 0.62 + 领先次优 margin 0.05 防边界摇摆）→ LLM 兜底 + 终端关键词安全网，逐层可单独关停与降级。【收益】高频固定指令 0ms 零网络调用命中、标准问法一次 embedding 命中、仅长难句下沉 LLM，成本与延迟显著下降；每条判定带 `layer` 落审计，误分类可定位到层。
- 【痛点】用 LLM 自动拆复合问法误拆难控（同主体多槽位追问被拆成两次检索），只能不断往提示词堆反例、成本随语言现象线性涨。【选型】主动**下线**自动拆句，改「用户显式点选 + `asyncio.gather` 并发委派 + 程序化分节合并不再过 LLM」，配 Semaphore 并发上限 + 逐位超时 + 异常隔离。【收益】零推断、完全可预期，单个智能体失败只降级自己那一节，合并环节不引入模型改写与编造。
- 【痛点】把专业智能体/业务系统做成一个大函数会耦合权限边界、无法独立演进；身份靠文本传递会被 LLM 误填或篡改。【选型】MCP（4 业务域 FastMCP）+ A2A（4 专业智能体）双协议，身份经协议级 `metadata` 下发、Agent Card 通告地址强制被配置端点覆盖。【收益】能力协议化后可被任何 MCP 客户端复用、新增业务域只加一个 server；可信身份不可被 LLM 篡改，杜绝被外部卡片引流到静默失败的下一步。
- 【痛点】靠 LLM「自觉」不越权不可靠，Text2SQL 一旦误操作会直连生产数据。【选型】角色×工具双层白名单默认拒（未列入白名单的工具对该角色**完全隐藏**，看不见也调不到）+ Text2SQL 沙盒只读护栏（单条 SELECT、关键字黑名单、表白名单、强制 LIMIT 与 `statement_timeout`）。【收益】默认拒绝的硬控制而非事后报错，LLM 因看不见工具就不会在回答里承诺能力，数据边界关在护栏与库权限层。
- 【痛点】只做窗口拼接记不住「用户是谁/发生过什么」，而每轮让 LLM 重总结画像又会随机丢字段、无法审计。【选型】三层记忆（Session 滚动窗口+溢出摘要 / Working State AsyncRedisSaver checkpoint / 个人六桶：画像按 key 确定性合并、情节带 `occurred_at` 时间锚 + 近 30 天窗口超 90 天降权、图谱落 Neo4j）+ 三类缓存并明确「只缓存无权限判定的纯函数、写操作与 A2A 整体不缓存」。【收益】读路径并行召回各桶单独降级、写路径一次 LLM 提取分桶落盘避免多轮调用；缓存既提速又不造成越权共享。

**智答 · 企业级多模态 RAG 知识底座（自研检索 + 生成链路）** · 独立设计与实现
`Python / FastAPI / PostgreSQL+pgvector / Elasticsearch / MongoDB / Redis / Neo4j / Ollama(bge-m3) / TEI(bge-reranker-v2-m3) / MinerU / Docker`
- 【痛点】纯向量对专名/条款编号/精确表述（如「FIN5000」「年休假」）召回差，而余弦距离、BM25 分、rerank 分三个尺度不可比、无法加权融合。【选型】pgvector 稠密 ANN（cosine + HNSW）与 Elasticsearch BM25 稀疏通道并行召回，RRF（k=60）**只融排名不融分数**；稠密通道只扫窄列、命中再按主键回表补正文。【收益】召回较单路向量 **+30%+**，RRF 无需调权重超参、对分数分布天然鲁棒，窄列 ANN + 回表显著降低排序扫描 IO。
- 【痛点】原实现用 Ollama `/api/embed` 取向量算 cosine 是「伪 rerank」——分数无 0~1 语义无法设阈值，且该 GGUF 在 Windows 调用即崩、热路径 1+N 串行把延迟放大一个数量级。【选型】迁到 TEI 独立容器跑 bge-reranker-v2-m3 **真 cross-encoder**（一个批量请求打完所有候选、`raw_scores=false` 直接给 sigmoid 相关性、进程级复用 `AsyncClient` 连接池、总超时 3s/建连 0.5s、单批上限 32 对齐 `max-client-batch-size`）。【收益】单条查询延迟从病态 **~28s 降到 0.59–1.30s**，分数具备可标定阈值语义；TEI 故障时健康探针大声 FAIL 并降级回 RRF 序（1.63s 不挂起）。
- 【痛点】把低相关噪声块喂给 LLM 会「幻觉变小说」，而各通道分数不可比导致无法在中途设统一阈值。【选型】确立「全链路唯一相关性阈值」——只在 rerank 之后设一道 0~1 置信阈值（默认 0.4，经真实数据标定：相关文档 0.83–0.92、噪声 ≤0.03）裁噪声，裁空即触发 judge 改写重检一次，仍空则固定话术拒答且不进 LLM。【收益】从根上杜绝噪声变小说、显著降低幻觉率，精排后 **Top-5 答案命中率 +25%**。
- 【痛点】多格式文档（扫描件/图片/复杂表格）解析难，固定长度切块要么截断上下文要么稀释 embedding，且重入库期间「旧块已删、新块未发」有检索空窗。【选型】多模态解析 + MinerU OCR（pdf 按真实页 / docx 按 Heading / pptx 按幻灯片 / xlsx 按工作表 / 表格按表头结构化保留）产出 section 级父块，结构感知**父子分块**（滑窗 512/overlap64，检索子块、组装父块）+ 正文三层存储（Mongo 正文 / PG 可索引窄行 / ES 可全量重建的派生倒排）+ expand-then-contract 单事务发布。【收益】解决扫描件无文本层与 Excel「答错列/断行」；切块 A/B **recall@10 +13.3%、MRR@10 +16.0%、nDCG@10 +17.1%、MAP@10 +20.6%**，同时上下文长度 **-29%**、证据密度 **+57%**，重入库无检索空窗。
- 【痛点】权限字段写进 JSONB 无法建索引也易被绕过；向量库与业务表分库时 ACL 变更要「读回整行含向量再 upsert」跨库同步。【选型】把向量迁到与业务表**同库**的 pgvector，ACL 走标量列（`visibility/owner_id/dept_id/allowed_roles`）冗余父子两表，向量 SQL 谓词 / ES bool filter / Python 复核三份实现语义逐条对应。【收益】权限热更新降为**同事务两条 UPDATE**（不动向量与 HNSW 索引），进 Context 前二次复核并区分「越权」与「库里没有」以避免存在性泄漏。
- 【痛点】改召回逻辑/切块/阈值全凭感觉，无法证明「变好了」。【选型】基于 MS MARCO 在**独立 PG 库 + 独立 ES 索引 + 独立 Mongo 库**跑 Recall/Precision/Hit/MRR/nDCG/MAP@k 与切块 A/B（评排序时阈值置 0 以免被置信裁剪污染）。【收益】混合检索绝对指标 **recall@10 0.9625、MRR@10 0.7597、nDCG@10 0.8059、Hit@10 0.9700**，切块与阈值改动有可复现 A/B 依据。

**马小i · 企业级 AI Agent 助手（端到端独立交付：后端 + 编排 + 前端 + 部署）**
`FastAPI / LangGraph / MCP / A2A / PostgreSQL+pgvector / Elasticsearch / Redis / Vue3 / Vite / Docker Compose`
- 【痛点】需求横跨后端编排与前端交互、还要内网私有化交付，拆给多人协作联调成本高。【选型】一人打通「LangGraph 单入口分层调度（上下文改写→三层意图漏斗→知识库/MCP/A2A 委派→记忆持久化）+ FastAPI 契约 + Vue3 前端 + Docker Compose 部署」。【收益】全链路 async、节点级 `trace_id` 审计，独立交付周期短、无跨端联调损耗。
- 【痛点】前端若硬编智能体名单/展示逻辑，后端一改路由前端就崩。【选型】以 Pydantic schema（`ChatRequest/ChatResponse`）定契约、`route` 为 Literal 枚举驱动前端展示形态、`GET /api/agents` 按角色白名单下发可委派清单。【收益】前后端解耦，新增智能体/新路由前端零硬编改动即可正确渲染。
- 【痛点】一次生成动辄几十秒，刷新或断网就整轮报废、体验差。【选型】前端 Vue3 + Element Plus + vue-element-plus-x 实现流式对话/思维链/多智能体结果分区/引用可点回溯，用 SSE + `Last-Event-ID` 断点续流，事件缓冲过期则降级拉已落库历史。【收益】刷新/断网不报废生成、断点可续传。
- 【痛点】内部系统直连生产数据，越权与敏感信息泄漏风险高。【选型】角色×工具双层白名单默认拒（隐藏工具对 LLM 不可见）+ 文档 ACL + 身份证/银行卡/手机号/金额脱敏 + SSRF 三重护栏 + Append-only JSONL 审计 + LangSmith/自建 Langfuse 双通道可观测。【收益】默认拒绝的硬控制、合规留痕，trace 与审计 `trace_id` 对齐可双向跳转。
- 【痛点】交付目标是内网单机可复现，K8s 过重、密钥易泄漏，且「宿主跑通但容器静默降级」会得出错误结论。【选型】Docker Compose 单机一键起 16 个服务（网关 + 4 MCP + 4 Agent + 6 存储/推理），密钥走 compose secrets 挂 `/run/secrets`（不进镜像/环境变量/git），容器为唯一验证环境 + 配置双轨 + 启动打印对接快照与 env-check 自检。【收益】一条 `up -d --build` 复现全栈、规避配置假阳性，服务边界已按 Deployment+Service 划好便于后续迁 K8s。

**智答 · 多模态 RAG 知识底座**（同 C-1，压缩到 4 条，仍保留痛点→收益）
- 【痛点→收益】纯向量对专名/编号召回差、分数尺度不可比 → pgvector 稠密 + ES BM25 稀疏并行 + RRF(k=60) + TEI 真 cross-encoder 精排 + 「唯一相关性阈值(0.4)」拒答 → 召回较单路 **+30%+**、Top-5 命中 **+25%**、噪声不进 LLM 抑制幻觉，精排延迟从 **~28s 降到 0.59–1.30s**。
- 【痛点→收益】固定切块截断上下文/稀释 embedding + 重入库检索空窗 → 结构感知父子分块 + 正文三层存储（PG 窄行/Mongo 正文/ES 派生倒排）+ expand-then-contract 单事务发布 → 切块 A/B **nDCG@10 +17.1%、上下文 -29%**，重入库无空窗。
- 【痛点→收益】权限写 JSONB 不可索引易绕过、分库 ACL 变更要跨库同步 → 向量与业务同库 pgvector + ACL 标量列冗余父子两表 + SQL/ES/Python 三份等价实现 → 权限热更新降为同事务两条 UPDATE，检索阶段租户级过滤「可检索即可见」。
- 【痛点→收益】改动无客观依据 → 独立 PG/ES/Mongo 评测库跑 MS MARCO 与切块 A/B → Recall/MRR/nDCG/MAP 可复现，混合检索 **recall@10 0.9625**。

### C-3 偏前端版（AI 交互前端为主角，后端/Agent 作为「懂链路」的加分项）

**AIGC 智能对话平台 · 前端主力开发**（2024.11 - 2025.01）
`React + Ant Design X + TypeScript + Markdown-it + Highlight.js + Vite`
- 【痛点】AI 回答是高频 token 流，每个 token 都 setState 会触发重排导致界面卡顿。【选型】ReadableStream + TextDecoder 解析流式数据 + `requestAnimationFrame` 合帧更新。【收益】毫秒级内容更新且不卡 UI。
- 【痛点】LLM 输出的 Markdown 流式中途标签未闭合会渲染错乱，带恶意标签有 XSS 风险。【选型】Markdown-it + 正则匹配与标签闭合检测 + 内容净化。【收益】流式渲染完整且安全，防 XSS。
- 【痛点】不同场景对回答深度/速度诉求不同，纯文字看不出推理过程。【选型】深度思考模式开关 + 推理过程结构化展示，消息气泡按内容类型差异化布局。【收益】满足深浅两档场景、推理可追溯。
- 【痛点】移动端/免打字录入需求。【选型】集成浏览器原生 SpeechRecognition API。【收益】语音到文本实时转换，识别准确率 95%+。

**马小i · AI Agent 助手（前端交互 + 全栈）**
`Vue3 / Vite / Element Plus / vue-element-plus-x / marked / DOMPurify / AntV G6 / SSE / FastAPI`
- 【痛点】后端 `route` 有知识库/工具/专业智能体/多智能体多种形态，前端一套气泡走天下会丢失引用来源与逐项成败。【选型】`BubbleList/XSender` 气泡流按 `route` 枚举切换展示形态（知识库带可点击引用来源、多智能体并发结果带逐项成败分区）。【收益】不同链路的结果都能正确可视化、引用可回溯。
- 【痛点】marked(GFM) 会把单个 `~` 当删除线定界符，AI 常写的中文区间「21~25℃」被误配成删除线、显示成「2125℃」；后端产物 `/api/...` 裸路径不可点。【选型】重写 `del` tokenizer 只认标准 `~~..~~`、用 TreeWalker 把正文 `/api/...` 自动包成可点 `<a>`（后端 `Content-Disposition` 触发同源下载）+ DOMPurify 净化。【收益】修掉区间显示错乱、产物路径可点下载，渲染安全防 XSS。
- 【痛点】一次生成几十秒，刷新/断网整轮报废。【选型】SSE + `Last-Event-ID` 断点续流，`localStorage` 持久化 `session_id / active_run_id / last_event_id` 支撑重进页面续传，深度思考开关与后端 `LLM_THINKING_ENABLED` 同向。【收益】刷新/断网不报废生成、重进可续。
- 【痛点】知识图谱/个人记忆是图结构，纯列表看不出关系。【选型】AntV G6 绘制图谱视图（节点抽稀、hover/zoom、标签显隐控制）+ 文件上传视图 + 记忆自服务管理页。【收益】图谱关系可视化、用户可自助管理记忆与上传文档。
- 【痛点】前端不懂后端链路会反复联调对不齐。【选型】能读 FastAPI + Pydantic 契约、理解三层意图路由与工具委派语义。【收益】与后端一次对齐角色白名单菜单、会话历史完整回填与降级路径，减少返工。
