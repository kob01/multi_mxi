# 简历可增补的 Agent 项目参考（结合本项目现状 + 2026 岗位趋势）

> 目的：现有两个锚定项目（智答 RAG + 马小i Agent）已经能撑起「Agent 编排 / RAG / MCP / A2A / 安全 / 私有化」。
> 2026 的 JD 反复追加四类要求：**长程任务规划、上下文工程、评测与可观测、GraphRAG/多模态、Human-in-the-loop 护栏、
> 成本/延迟 SLO**。下面每个项目都标注了「与仓库的关系」和「可写程度」，避免简历写了面试兜不住。
>
> 可写程度：
> - **可直接写**：仓库已实现或已有明确基础设施，补几句包装即可。
> - **半真半包装**：核心链路已具备，缺一个把能力串成产品的小 demo，1-2 天能补出来。
> - **需先做 demo**：目前仓库没有，建议先跑通最小可复现再写（GitHub 有源码最稳）。

---

## P1. Deep Research 深度调研 Agent（长程任务规划 + 引用聚合 + 报告导出）· 半真半包装
**趋势点**：JD 里的「能做长程任务 Agent，而不是只调用一次模型」「Plan-and-Execute / 反思回环」。
**仓库基础**：已有 web 检索 + `fetch_url`、RAG 检索、docgen（PDF/DOCX/PPTX/XLSX/Markdown 导出）、LangGraph 条件边回环。
**技术栈**：LangGraph / ReAct + Plan-Execute / MCP 检索工具 / docgen / 引用溯源

- 设计「规划 → 子问题分解 → 多轮检索取证 → 交叉验证 → 结构化报告」的长程链路，用 LangGraph 的回环边实现「证据不足就重检索」的自我纠错，设最大步数与 token 预算防止失控。
- 每个结论句强制绑定检索证据（source/score 元数据），无证据的句子标「待核实」，把幻觉抑制从 RAG 单轮扩展到多步研究。
- 产物直接走 docgen 落成带引用脚注的 PDF/Word，前端给可点下载链接。

**简历写法**：一条「实现 Deep Research Agent，支持任务规划与多轮取证-反思回环，输出带引用溯源的调研报告，端到端取代人工资料搜集」。

## P2. Agent 评测与可观测体系（LLM-as-Judge + 回归集 + 工具调用准确率/幻觉率/成本 SLO）· 可直接写（扩写）
**趋势点**：几乎所有中高级 JD 都写「建立评测体系，用数据证明 Agent 变好」，点名 SWE-bench / AgentBench / TAU-bench。
**仓库基础**：已有 MS MARCO 检索评测 + 切块 A/B（独立库隔离，指标 Recall/MRR/nDCG/MAP）、LangSmith + 自建 Langfuse 双通道、审计 JSONL（trace_id 串联、`score_mode`/`acl_blocked`/`cache_hit` 等降级事实字段）。

- 在检索评测之上补 **端到端 Agent 评测**：任务完成率、工具调用准确率（选对工具 + 参数正确率）、引用正确率、幻觉率，用 LLM-as-Judge + 人工抽检双轨。
- 以固定问答回归集卡门禁：改提示词/路由/模型前后跑同一集，指标不许劣化（对应仓库里「独立评测库不污染生产」的做法）。
- 用 Langfuse 自建栈做成本/延迟观测，把 trace 与审计 `trace_id` 对齐实现双向跳转，输出「每轮 token 成本 / P95 延迟」看板。

**简历写法**：一条「搭建 Agent 评测与可观测闭环：IR 指标（Recall/MRR/nDCG/MAP）+ 端到端任务/工具/引用正确率回归集，LLM-as-Judge + 人工抽检，Langfuse 自建观测成本与延迟」。

## P3. GraphRAG / 知识图谱增强问答（多跳 + 社区摘要）· 半真半包装
**趋势点**：架构师/高级岗明确写「深入理解 RAG/GraphRAG」「检索/重排、多 Agent 调度」。
**仓库基础**：已有 `app/kg`（实体关系抽取、图存储、词表控制）与 Neo4j 个人记忆图谱，向量+图混合已是设计目标。

- 用 LLM 从文档抽取实体-关系入 Neo4j，检索时「向量召回定位种子节点 → 图多跳扩展邻居 → 社区摘要补全局语境」，解决「跨文档、需要把多条制度串起来才能回答」的多跳问题。
- 与 ACL 打通：图遍历也带角色可见性谓词，越权邻居不进 Context。
- 与纯向量 RAG 做对比：多跳/汇总类问题的命中率与「答案能否覆盖分散在多篇文档的要点」的提升。

**简历写法**：一条「在向量+稀疏混合检索上引入 GraphRAG：LLM 抽取实体关系入 Neo4j，检索做种子定位+多跳扩展+社区摘要，改善跨文档多跳与全局汇总类问题，并保持图遍历的权限一致性」。

## P4. 多模态文档智能（图表理解 + 表格问答 + 图文混合检索）· 半真半包装
**趋势点**：RAG 全链路标配已升级为「多模态解析」，企业文档大量是扫描件、复杂表格、PPT 图表。
**仓库基础**：已有 MinerU OCR、docx/pptx/xlsx/pdf 结构化解析、父子分块；已处理「Excel 合并单元格/裸值切块答错列」这类真实坑。

- 扫描件与图片走 MinerU，表格类内容按「表头对齐 + 结构化保留」切块（避免合并单元格错位、跨行断列），支持「按表格问答」。
- PPT/图表图像可用多模态模型生成描述后再检索，图与文进同一向量空间/同一 ACL 语义。
- 图片型证据在答案里带缩略图与原文回溯。

**简历写法**：一条「扩展 RAG 到多模态：MinerU OCR + 表格结构化切块解决合并单元格/断列错位，图表转述入检索，支持扫描件与复杂表格问答，并保持图文一致的权限门禁」。

---

## P5. Browser / Computer-Use 自动化 Agent（表单代填 + 进度查询）· 需先做 demo
**趋势点**：2026 热点之一，「长程任务 + 工具调用 + 界面操作」，把「查进度慢、填表单烦」这类员工痛点真正自动化。
**仓库基础**：马小i 已解决「多系统找入口难」，MCP 已封装历史系统接口；可把「网页系统」也纳入一类可委派能力。

- 基于 Playwright/浏览器 MCP，用视觉或 DOM 定位完成登录态下的表单代填与页面信息抓取；关键写操作走 Human-in-the-loop 二次确认。
- 与安全护栏统一：SSRF、可操作域名白名单、敏感字段脱敏、逐步操作审计留痕。

**简历写法**：一条「构建 Computer-Use 自动化 Agent，经浏览器/Playwright 在受控白名单内代填表单与查询进度，敏感操作引入人工确认，纳入统一审计与 SSRF 防护」。
**注意**：没做过就别写「精通」，写「设计与原型」更稳。

## P6. Human-in-the-loop 审批式 Agent 与 Guardrails（敏感操作二次确认 + 越权拦截）· 可直接写（扩写）
**趋势点**：JD 常写「权限边界、异常恢复、安全边界遵守率」「工具调用避免越权执行」。
**仓库基础**：已有角色×工具双层白名单默认拒、文档 ACL、Text2SQL 只读护栏、权限拒绝补审计（`mcp_permission_denied`/`a2a_permission_denied`）。

- 把「报销提交、工单创建、SQL 执行」等写操作/高危操作定义为需确认动作：模型给出计划 → 用户/规则确认 → 才执行，形成 plan-then-confirm 闭环。
- Guardrails 分层：输入侧意图/越权预判，输出侧敏感信息脱敏与存在性泄漏防护，执行侧库权限 + 只读护栏。

**简历写法**：一条「设计敏感操作的 Human-in-the-loop 与分层 Guardrails：写操作计划先确认后执行，角色×工具默认拒 + 文档 ACL + Text2SQL 只读护栏 + 脱敏，权限拒绝全量审计」。

---

## P7. 上下文工程与长期记忆系统专项（Context Engineering）· 可直接写（独立成故事）
**趋势点**：2026 把「上下文工程」单列成核心能力，「优化上下文、记忆与任务状态管理」。
**仓库基础**：三层记忆（Session 滚动窗口+摘要 / Working State checkpoint / 个人六桶：画像确定性合并、情节带时间锚与衰减、图谱）、三类缓存、指代消解前置于意图识别。

- 把「记忆」从零散实现抽成一个可讲专题：读路径并行召回、各桶单独降级；写路径一次 LLM 提取分桶落盘；情节近 30 天窗口、超 90 天降权；画像限 `profile_max_chars` 防越滚越大。
- 上下文预算：按 token 预算裁剪注入（画像/情节/检索证据/工具结果各占配额），保证「塞进 Prompt 的都是该塞的」。

**简历写法**：可作为个人优势或 Agent 项目里的一条，也可独立成一个「长期记忆与上下文工程」小项目。

## 用法建议（三方向各挑几个）
- **纯 AI 应用**：主推 P2 评测可观测 + P3 GraphRAG + P6 Guardrails（体现架构深度与工程质量），P1/P7 作亮点。
- **偏全栈**：P1 Deep Research（端到端含导出）+ P5 Computer-Use + P2 观测看板（前后端都能讲）。
- **偏前端**：P1/P5 的交互与执行可视化（规划步骤流、工具调用时间线、引用回溯、图谱可视化）是前端最佳加分项。

> 提醒：宁可写 3 个讲得透的，也不要堆 7 个名词。面试官一定会顺着一个点往「为什么这么选、踩过什么坑、指标怎么来的」三连追问。
