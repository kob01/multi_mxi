# 意图识别三层漏斗改造

## 目标与总体流程
把 [IntentRecognizer.classify()](file:///d:/ai/mxi/app/assistant/intent.py) 从「总是调用 LLM、失败才关键词兜底」改为按成本/确定性逐级下沉的漏斗：

```
message -> 第一层 规则快筛(正则/关键词, 同步零成本) --命中--> 返回(conf~0.9)
              |未命中
         -> 第二层 bge-m3 语义分类(一次 embedding, 命中即返回)  --命中--> 返回
              |未命中/相似度不足
         -> 第三层 LLM(deepseek, 现有 INTENT_PROMPT)  --成功--> 返回
              |异常
         -> 关键词启发式 _fallback(终端安全网, 保留现有逻辑)
```

命中判定口径（已与用户确认）：第二层用「每个意图取 Top-K 最相似种子的余弦相似度均值」，最优意图得分 ≥ 接受阈值、且领先次优 ≥ 间隔阈值才命中；否则下沉 LLM。

## app/assistant/intent.py 重构（核心）
新增两张内置常量表 + 三层方法 + 懒加载向量缓存，`classify()` 改为串联漏斗。

- 第一层 规则表 `_RULES: list[tuple[re.Pattern, IntentType, target|None]]`，按序匹配、命中即高置信返回：
  - 查单号/余额/进度类（复用现有 `_TOOL_PATTERNS` 思路，如 `FIN\d+|HR\d+|单号|余额|进度|签到|打卡`）→ `TOOL_CALL`，按域关键词给 target(finance/hr)。
  - 办理类（`报销|开发票|开.*证明|离职|入职`）→ `AGENT_DELEGATE` + target。
  - `reason` 前缀标注 `rule:`，便于审计区分层级。
  - 规则表设计为易扩展的常量列表；示例命令（转人工/查订单号/签到）以现有四类意图体系落地，不新增意图枚举。
- 第二层 种子表 `_SEEDS: dict[(IntentType, target|None), list[str]]`，为 knowledge_qa / tool_call(finance,hr) / agent_delegate(finance,hr) / chitchat 各写 6-10 条代表话术（复用 prompts/关键词表中的既有语料，如"年假有几天""查询 FIN5000 报销单""我要报销""你好"）。
  - `async _ensure_seeds()`：首次调用时用 [OllamaEmbedder](file:///d:/ai/mxi/app/rag/embeddings.py) 批量 embed 所有种子、做 L2 归一化并按 (intent,target) 缓存到 `self._seed_index`（进程内单例，只建一次）；embedding 服务不可用时置标记、本层跳过。
  - `async _semantic_classify(query)`：embed_query 归一化 -> 与各组种子算余弦（归一化向量点积）-> 每组取 Top-K 相似度均值 -> 最优/次优判定 -> 命中返回 `IntentResult(intent, target, confidence=best, reason="embed:...")`，否则返回 None。
  - 全程 try/except：任何异常（Ollama 未启、维度不符）返回 None 下沉，绝不影响主链路。
- 第三层 `_llm_classify()`：抽出现有 [classify()](file:///d:/ai/mxi/app/assistant/intent.py) 主体（INTENT_PROMPT + json 解析），成功返回、异常返回 None；`reason` 前缀 `llm:`。
- `_fallback()`（终端安全网）：保留现有关键词启发式实现不变。
- `classify(message, history)`：按漏斗顺序 rule -> semantic -> llm -> fallback 组装，用改写后的独立问题做 embedding 输入（复用 graph 传入的 query）。

## app/config.py 新增可配置项（第二层阈值/开关）
在 Settings 内追加，默认值保守、可 env 覆盖：
- `intent_embedding_enabled: bool = True`（关闭即跳过第二层）
- `intent_semantic_top_k: int = 3`
- `intent_accept_threshold: float = 0.62`
- `intent_margin: float = 0.05`

## app/schemas.py 观测增强（可选、轻量）
给 [IntentResult](file:///d:/ai/mxi/app/schemas.py) 增加 `layer: Optional[str]`（rule/embedding/llm/fallback），便于 `classify_intent` 节点审计区分命中层；不改现有路由逻辑，仅记录。

## graph.py 影响评估
[classify_intent](file:///d:/ai/mxi/app/assistant/graph.py) 节点与 [_route_by_intent](file:///d:/ai/mxi/app/assistant/graph.py) 无需改动：仍消费 `IntentResult`、仍按 intent 路由。仅 `reason`/`layer` 内容更丰富，审计字段自动透出。

## 测试计划
- `python -c` 直接跑 `IntentRecognizer().classify()` 冒烟：
  - 规则样例（"查询 FIN5000 报销单进度""帮我签到"）应在第一层命中（reason=rule: 且不调用后续层）。
  - 语义样例（"年假能休几天""怎么开在职证明"）在第二层命中（reason=embed:）。
  - 边界/长难句下沉第三层（reason=llm:）。
  - Ollama 关闭时第二层自动跳过、LLM 关闭时回退关键词（reason=fallback/keyword）。
- 校验阈值边界：调 `intent_accept_threshold` 高低对下沉比例的影响（临时打印各层得分）。

## 假设
- bge-m3 走本地 Ollama（`ollama_base_url`/`embedding_model`），与 RAG 检索共用同一 embedder。
- 不新增 IntentType 枚举；「转人工/签到」等固定指令映射到现有四类意图 + target。
- 种子集为代码内置常量，随版本演进，不引入外部数据文件与加载校验逻辑。
